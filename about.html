Câu 1 (10 điểm): position: absolute vs position: relative

1. Sự khác biệt cốt lõi:

  • position: relative: Định vị tương đối so với vị trí mặc định ban đầu của chính nó trong luồng tài liệu (normal flow). Phần tử vẫn chiếm không gian ban đầu của nó, các phần tử xung quanh không bị dịch chuyển lấp chỗ trống. Nó thường được dùng làm "khung chứa mẹ" (containing block) cho các phần tử con tuyệt đối bên trong.
  • position: absolute: Định vị tuyệt đối tách hoàn toàn khỏi luồng tài liệu thông thường. Nó được định vị so với phần tử cha gần nhất có thuộc tính position khác static (như relative, absolute, fixed). Nếu không có, nó sẽ căn cứ vào thẻ gốc <html>. Không gian ban đầu của nó bị xóa bỏ và các phần tử khác sẽ lấp vào chỗ trống.

2. Tình huống sử dụng tạo layout responsive:

  • Relative: Dùng cho khung thẻ bao bọc (wrapper container) của một card sản phẩm hoặc banner, giúp định hình không gian lưới mà không làm hỏng cấu trúc layout chung.
  • Absolute: Dùng để đặt các huy hiệu (badge như "Giảm giá 50%", "Hot", "New") đè lên góc của ảnh sản phẩm hoặc nút "Đóng" (Close button) ở góc trên bên phải của Modal popup.

3. Ảnh hưởng khi deploy website lên hosting:

Khi deploy lên các nền tảng hosting tĩnh (như GitHub Pages hay Netlify), việc sử dụng position: absolute dựa trên các giá trị cứng (pixels tuyệt đối như top: 150px; left: 300px;) rất dễ gây vỡ giao diện (overflow) khi hiển thị trên màn hình di động nhỏ (responsive mobile). Giải pháp tối ưu là kết hợp đơn vị phần trăm (%), Flexbox, hoặc Grid để đảm bảo tính tương thích cao trên mọi thiết bị.

Câu 2 (10 điểm): Quy trình Domain & Hosting, Vai trò DNS & Deploy

1. Quy trình đăng ký domain và cấu hình hosting cho website JavaScript:

  • Bước 1 (Mua Domain): Đăng ký tên miền tại nhà cung cấp (Namecheap, GoDaddy, P.A Việt Nam...) với tên miền định danh (ví dụ: nhannt-vhu.io.vn).
  • Bước 2 (Chuẩn bị Source Code): Hoàn thiện mã nguồn tĩnh website bao gồm HTML, CSS, JavaScript thuần (có thể lưu trữ dữ liệu client-side qua LocalStorage hoặc tích hợp API bên ngoài).
  • Bước 3 (Chọn Hosting/PaaS): Đưa code lên nền tảng hosting phù hợp cho ứng dụng tĩnh/JS như GitHub Pages, Netlify hoặc Vercel.
  • Bước 4 (Cấu hình DNS trỏ về Hosting): Đăng nhập trang quản lý tên miền, cấu hình các bản ghi DNS (như bản ghi CNAME hoặc A Record) để liên kết tên miền riêng với URL server hosting cung cấp.

2. Vai trò của DNS (Domain Name System):

DNS đóng vai trò như "danh bạ internet", dịch tên miền dễ đọc (ví dụ: nhannt-vhu.io.vn) thành địa chỉ IP máy chủ số học (ví dụ: 185.199.108.153) để trình duyệt máy khách có thể tìm và kết nối chính xác tới website.

3. Đề xuất 2 công cụ deploy không cần server riêng:

  • GitHub Pages: Miễn phí, tích hợp trực tiếp với kho lưu trữ Git, tự động build và deploy website tĩnh qua mỗi lần git push.
  • Netlify: Hỗ trợ kéo-thả (drag-and-drop) thư mục code lên để deploy lập tức, hỗ trợ tự động cấu hình chứng chỉ SSL miễn phí (HTTPS) và custom domain cực nhanh.

4. Rủi ro bảo mật nếu không cấu hình đúng:

Không cấu hình HTTPS (chứng chỉ SSL) dẫn đến dữ liệu truyền tải giữa người dùng và website bị nghe lén (Man-in-the-Middle Attack). Cấu hình bản ghi DNS sai (ví dụ phân quyền nhầm CNAME takeover) có thể khiến hacker chiếm quyền kiểm soát tên miền trỏ về website độc hại.

Câu 3 (10 điểm): So sánh let, const và var trong JavaScript

1. Bảng so sánh Scope và Hoisting:

  • var: Function scope (hoặc Global scope nếu khai báo ngoài hàm). Có hỗ trợ hoisting nhưng khởi tạo giá trị là undefined, dễ gây lỗi logic ẩn. Cho phép khai báo lại trùng tên.
  • let: Block scope (phạm vi trong cặp ngoặc nhọn {}). Có hoisting nhưng nằm trong Temporal Dead Zone (TDZ) nên gọi trước khi khai báo sẽ văng lỗi ReferenceError. Không cho phép khai báo lại cùng một scope.
  • const: Block scope giống let. Bắt buộc phải gán giá trị ngay khi khai báo và không thể gán lại giá trị mới (immutable binding, tuy nhiên với object/array vẫn thay đổi được thuộc tính bên trong).

2. Ví dụ lỗi thường gặp và cách Debug:

// Lỗi TDZ với let hoặc gán lại const
try {
    console.log(score); // Lỗi ReferenceError: Cannot access 'score' before initialization
    let score = 100;
} catch (err) {
    console.error(err.message);
}

Cách Debug bằng Chrome DevTools: Nhấn F12 hoặc chuột phải chọn Inspect, mở tab Sources, đặt các điểm dừng (Breakpoints) tại dòng code nghi vấn, sau đó quan sát khung Scope (Local, Closure, Global) để theo dõi trạng thái biến hoặc gõ trực tiếp biểu thức vào tab Console để kiểm tra.

Câu 4 (10 điểm): Event Delegation trong JavaScript

1. Khái niệm Event Delegation (Ủy quyền sự kiện):

Event Delegation là kỹ thuật tận dụng tính năng Event Bubbling (nổi bọt sự kiện). Thay vì gắn trực tiếp một sự kiện lắng nghe (như addEventListener) lên từng phần tử con riêng lẻ, ta gắn một sự kiện duy nhất lên phần tử cha chung của chúng. Khi sự kiện xảy ra ở phần tử con, nó sẽ nổi bọt lên phần tử cha và phần tử cha sẽ kiểm tra event.target để xử lý phù hợp.

2. Ứng dụng trên danh sách động (Dynamic List):

// Ví dụ xử lý click trên danh sách thêm mới động
const ulList = document.querySelector('#dynamicList');
ulList.addEventListener('click', function(e) {
    if (e.target && e.target.nodeName === 'LI') {
        alert('Bạn đã click vào mục: ' + e.target.textContent);
    }
});

3. Lợi ích tích hợp với HTML/CSS tối ưu hiệu suất:

  • Giảm thiểu số lượng bộ lắng nghe sự kiện (event listeners) gắn trên DOM, tiết kiệm đáng kể bộ nhớ RAM của trình duyệt khi danh sách có hàng ngàn phần tử.
  • Tự động hoạt động hiệu quả với các phần tử con mới được thêm vào động sau này mà không cần gọi lại hàm gán sự kiện thủ công.
